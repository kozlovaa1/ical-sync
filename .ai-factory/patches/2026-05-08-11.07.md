# Compose port binding aligned with configurable app PORT

**Date:** 2026-05-08 11:06
**Files:** docker-compose.yml, docker-compose.traefik.yml, docs/deployment.md
**Severity:** high

## Problem

Deployment configuration and documentation allowed changing `PORT`, but runtime wiring still hardcoded container/Traefik target port `3000`. With non-default `PORT`, the app could listen on one port while Docker publish and Traefik upstream pointed to another.

## Root Cause

A partial migration to standalone + optional Traefik overlay updated docs and env descriptions, but compose runtime mappings were not updated consistently. This created a config-contract mismatch between documented behavior and actual routing.

## Solution

Updated compose wiring to reference `PORT` consistently:
- `docker-compose.yml` ports mapping changed to `${HOST_PORT:-3000}:${PORT:-3000}`
- `docker-compose.traefik.yml` load balancer port changed to `${PORT:-3000}`
- `docs/deployment.md` updated to reflect effective mapping and overlay port behavior

## Prevention

- For config-related changes, verify all transport layers use the same source variable (app bind, container mapping, reverse-proxy target).
- Add a compose-level regression check in review: `docker compose ... config` with non-default `PORT`.
- During review, cross-check docs claims against executable config, not only file comments.
