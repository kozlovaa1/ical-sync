# Compose port check failed in CI without .env

**Date:** 2026-05-08 14:30
**Files:** scripts/check-compose-ports.sh
**Severity:** medium

## Problem

GitHub Actions job `test` failed with exit code 1 after successful dependency install, build, and Vitest run. The failing step was `Compose port regression check`, where `docker compose config` exited with:

`env file /home/runner/work/ical-sync/ical-sync/.env not found`

## Root Cause

The regression script rendered `docker-compose.yml` directly. That Compose file declares `env_file: .env`, which is valid for deployment but inappropriate as a hard requirement for CI config rendering because `.env` is intentionally untracked and secret-bearing.

The test assumed that variable overrides like `PORT=3100 HOST_PORT=3900` were enough for `docker compose config`, but Compose validates service-level `env_file` existence before rendering the merged config.

## Solution

Updated `scripts/check-compose-ports.sh` to detect a missing `.env`. When absent, the script creates a temporary Compose workspace, copies the Compose files, copies `.env.example` as `.env`, and renders config from that temporary directory. Existing local `.env` files remain untouched.

Added a diagnostic log prefix `[FIX:compose-env]` for the fallback path so CI logs clearly show why `.env.example` was used.

## Prevention

- CI checks that render Compose config should not require untracked secret files.
- When Compose uses `env_file`, test config rendering in a workspace without `.env`.
- Keep `.env.example` complete enough for non-secret config validation.
