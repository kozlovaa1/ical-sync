# Базовые правила проекта

> Автоопределённые соглашения по текущему TypeScript/Fastify-коду. Обновляйте при изменении структуры или технологий.

## Соглашения об именовании
- Файлы: `kebab-case`.
- Переменные: `camelCase`.
- Функции: `camelCase`.
- Классы: `PascalCase`.

## Структура модулей
- `src/http/` — HTTP-роуты и middleware.
- `src/integrations/` — клиент внешнего календарного сервиса.
- `src/ical/` — формирование/валидация iCal-ответа.
- `src/config/` — загрузка и валидация конфигурации.
- `src/services/` — бизнес-логика, кеширование и fallback-поведение.
- `src/observability/` — структурированное логирование и маскирование чувствительных данных.
- `test/` — unit и route-тесты Vitest.

## Обработка ошибок
- Внутри интеграций: нормализация ошибок внешнего API в внутренние типы ошибок.
- На HTTP-уровне: маппинг ошибок в стабильные статус-коды и безопасные сообщения.
- Неверный public token для календаря должен возвращать `404`, а не `401`, чтобы не раскрывать наличие защищённого ресурса.
- Ошибки upstream без stale cache отображаются как безопасный `502 Bad Gateway`.

## Логирование
- Структурированные логи с уровнями (`debug`, `info`, `warn`, `error`).
- Никогда не логировать секреты (`password`, `token`, `Authorization`, cookie).
- Не логировать тело календаря, полный secret-bearing URL или значение `PUBLIC_TOKEN`.

## Тестирование
- Использовать Vitest.
- Route-тесты должны проверять HTTP-коды, безопасные тела ошибок, заголовки `Content-Type`/`Cache-Control` и отсутствие утечки токенов в логах.
- Service-тесты должны покрывать TTL cache, stale fallback, валидацию iCal и классификацию ошибок upstream.
