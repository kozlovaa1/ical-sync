# Прокси iCal для защищённого календарного сервиса

## Обзор
Сервис предоставляет HTTP-эндпоинт, который возвращает календарь в формате iCal (`.ics`), получая исходные данные из запароленного внешнего сервиса. Прокси скрывает детали авторизации и выдает стандартизированный iCal-ответ для клиентов календарей.

## Ключевые возможности
- Получение календарных данных из внешнего защищённого сервиса по учётным данным/токену из конфигурации.
- Преобразование или проксирование ответа в валидный формат iCal (`text/calendar`).
- Контролируемое логирование без утечки секретов.

## Технологический стек
- **Язык:** TypeScript (Node.js 22 LTS или более новый LTS runtime)
- **Фреймворк:** Fastify
- **База данных:** Не требуется (MVP)
- **ORM:** Не требуется
- **Интеграции:** Внешний запароленный календарный сервис (по HTTP/HTTPS)
- **Тесты:** Vitest
- **Деплой:** Docker + Docker Compose (standalone) с optional Traefik overlay для HTTPS/домена

## Архитектурные заметки
Реализовано разделение на HTTP-слой (`src/http/routes.ts`), сервисный слой (`src/services/calendar-service.ts`), интеграционный слой (`src/integrations/calendar-source.ts`), слой валидации iCal (`src/ical/validate-calendar.ts`) и слой конфигурации/логирования (`src/config/env.ts`, `src/observability/logger.ts`). Секреты хранятся только в переменных окружения.

## Нефункциональные требования
- **Логирование:** Уровень через `LOG_LEVEL`, без вывода паролей/токенов.
- **Обработка ошибок:** Предсказуемые HTTP-коды и безопасные сообщения клиенту.
- **Безопасность:** TLS до внешнего сервиса, валидация входных параметров, ограничение частоты запросов при необходимости.
- **Кеширование:** In-memory TTL cache со stale fallback при недоступности upstream.
